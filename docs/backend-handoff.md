# 백엔드 전달 사항

- 작성일: 2026-11-11
- 보내는 쪽: 프론트 담당
- 받는 쪽: 백엔드 담당
- 배경: 프론트 코드를 이 저장소로 분리했고(2026-11-10), 개인정보처리방침·약관을 실제 코드와 대조해 고쳤습니다(검토 기록 `docs/2026-11-10-privacy-review.md`). 그 과정에서 백엔드 쪽에서 처리하거나 알고 있어야 할 것을 모았습니다.

아래 파일 경로 중 `src/server/...`, `supabase/...`는 전체 앱 저장소(`hjaehyun/webTest`) 기준입니다.

## 1. 고쳐야 하는 것

### 1-1. 탈퇴할 때 그림 파일이 남을 수 있음 (우선)

- 방침 문장: "탈퇴하면 계정·조각글·그림·그림 파일·전시를 바로 모두 지워요"
- 실제: `src/server/db/images.ts`의 `removeUserImages`가 실패해도 경고만 남기고 끝나며, `DELETE /api/me`는 그대로 계정을 지웁니다. 그러면 주인 없는 그림 파일이 버킷에 남습니다.
- 요청: 둘 중 하나로 맞춰 주세요.
  1. 파일 삭제가 실패하면 탈퇴를 멈추고 오류를 돌려주기(사용자가 다시 시도)
  2. 계정은 지우되, 남은 파일을 나중에 지우는 정리 작업 두기(예: 자동 마감 cron에서 주인 없는 폴더 삭제)
- 끝난 기준: 파일 삭제가 실패하는 경우를 시험해도 탈퇴 후 `artworks/<user_id>/`에 파일이 남지 않음.

### 1-2. 노래 목록 30일 삭제가 요청이 있을 때만 실행됨

- 방침 문장: "30일이 지나면 추천에 쓰지 않고 지워요"
- 실제: 30일 지난 곡은 추천에서 빠지지만(`pick_song`), 삭제는 누군가 노래를 요청할 때만 실행됩니다(`src/server/db/songs.ts`의 cleanup). 요청이 없으면 계속 남습니다.
- 요청: 자동 마감 cron(B20)을 만들 때 `song_pool` 정리도 같이 넣어 주세요. 개인 정보는 아니라 급하지 않습니다.

## 2. 지금 동작을 유지해 주세요 (방침에 적은 약속)

방침은 아래 동작을 전제로 적혀 있습니다. 바뀌면 방침이 틀리게 되니, 바꾸기 전에 프론트 담당에게 알려 주세요.

| 약속 | 근거 코드 |
|---|---|
| 위치 좌표는 날씨 조회에만 쓰고 저장·로그하지 않음. 기상청에는 격자 번호만 보냄 | `src/app/api/me/entries/route.ts`, `src/server/weather/index.ts` |
| Gemini에는 조각글·시각·날씨만 보냄. 닉네임·이메일은 보내지 않음. `store:false` | `src/server/ai/gemini.ts`, `src/server/ai/lines.ts` |
| 큐레이터는 기간 이름·그림 수·태그·장면 요약만 보냄 | `POST /api/curate` 입력(`CurationInput`) |
| Cloudflare에는 영어 그림 설명과 고정 그림체 문구만 보냄 | `src/server/ai/image.ts` |
| 공개 전시 응답에 조각글·이메일·사용자 식별자가 없음. 나가는 것은 전시 제목·소개글, 닉네임, 그림, 날짜, 장면 요약, 설명, 노래 | `src/server/db/publicExhibition.ts` |
| 조각글 수정·삭제는 마감 전까지만. 그림은 삭제 없이 다시 그리기만 | `supabase/schema.sql` RLS 정책 |
| 탈퇴하면 모든 테이블의 내 기록이 함께 삭제됨 | 각 테이블 `on delete cascade` |
| 쿠키는 로그인용(`sb-*`)과 소셜 로그인 중 임시 쿠키뿐 | `src/server/supabase.ts`, `src/server/oauth.ts` |
| 배포 로그에 사용자 식별자·검색어를 남기지 않음 | `DEBUG_SECURITY`를 Vercel에서 켜지 않기(`src/server/debug.ts`). 켜면 `userId`, 노래 검색어가 로그에 남음 |

다음 변경은 방침을 다시 고쳐야 하므로 꼭 알려 주세요.

- 새 외부 서비스에 데이터를 보낼 때
- 새 컬럼·테이블에 사용자 정보를 저장할 때 (예: 조각글 사진)
- 공개 전시 응답에 필드를 더할 때
- 그림·마감한 날 기록을 지우는 기능을 만들 때 (방침 5절을 다시 써야 함)

## 3. 판단을 부탁하는 것

### 3-1. AI가 쓴 검색어·그림 설명의 개인 정보 걸러내기

- 실제: 노래 검색어(`isSafeSongQuery`)와 그림 설명(`isSafeImagePrompt`)은 숫자·`@`·링크만 막습니다. 이름·장소는 Gemini에게 "넣지 말라"고 지시할 뿐입니다.
- 방침에는 이 상태 그대로 적었습니다("숫자·주소는 걸러내고, 이름·장소는 넣지 않도록 AI에 지시해요").
- 질문: 더 막을지(예: 조각글에 나온 고유 단어가 검색어에 그대로 들어가면 고정 검색어로 대체) 정해 주세요. 그대로 둬도 방침과는 맞습니다.

## 4. 프론트 작업이 기다리는 API

간트 차트에서 프론트 작업과 짝이 되는 백엔드 작업입니다. 형식을 먼저 정해 주면 화면을 맞춰 만들겠습니다.

| 프론트 | 백엔드 | 정해야 할 것 |
|---|---|---|
| F10 이미지 첨부 UI·미리보기 | B11 이미지 업로드 API | 경로와 메서드, 보내는 형식(multipart 등), 크기·형식 제한, 응답(파일 경로 또는 서명 URL), 조각글과 연결하는 방법, `GET /api/me` 응답에서 사진이 어떤 필드로 오는지. **사진 저장은 새 개인 정보라 방침도 같이 고쳐야 함** |
| F21 전시회 여러 개 | B25 전시회 여러 개 | 지금은 `GET /api/me`의 `exhibition`(1개)과 `PATCH /api/me/exhibition`. 여러 개가 되면 목록·만들기·지우기 경로와 응답 형식 |
| F12 그리는 중 표시 | B20 자동 마감 cron | 자동 마감된 날이 `GET /api/me`에 어떤 상태(`drawing`/`done`/`failed`)로 오는지, 실패한 날을 사용자가 다시 시도할 수 있는지 |
| F15 AI 한도 초과 문구 | B19 AI 사용 한도 | 지금처럼 `429` + `{ "error": "..." }` 유지. 화면은 `error` 문장을 그대로 보여 줌 |

프론트가 부르는 API 전체 목록은 `README.md`의 "프론트가 부르는 API" 표, 요청·응답 데이터 모양은 `src/lib/types.js`(주석으로 적은 설명 문서, 전체 앱의 `src/lib/types.ts`와 같은 내용)에 있습니다. 오류 응답은 모두 `{ "error": "사용자에게 보여 줄 문장" }` 형식을 전제로 합니다(`src/lib/store.jsx`의 `api()`).

## 5. 이 저장소에 복사해 둔 백엔드 파일

| 파일 | 상태 |
|---|---|
| `src/server/supabase.js`, `src/server/auth.js` | 소셜 로그인 라우트가 쓰는 공용 도우미. **원본 `.ts`에서 타입 표기만 지운 사본**이며 여기서는 동작을 고치지 않습니다. 원본이 바뀌면 알려 주세요 |
| `src/lib/mockSong.js` | 원본 `src/server/music/mock.ts`의 `isMockVideo` 한 줄을 옮긴 것. 모의 곡 id 앞글자 `MOCK_`를 바꾸면 알려 주세요 |
| `src/app/api/auth/oauth/`, `src/app/api/auth/callback/`, `src/server/oauth.js` | 소셜 로그인(B9). 프론트 담당이 맡은 작업이라 이 저장소에서 관리 |

## 7. 배포 관련

- 고친 방침·약관은 전체 앱 로컬 사본에도 넣어 두었지만, `hjaehyun/webTest`에 push하기 전이라 배포 사이트는 이전 문구입니다. 시행일은 2026-11-10으로 적혀 있어, push가 늦어지면 날짜를 맞춰야 합니다.
- 2026-11-11 이 저장소에서 두 가지를 바꿨습니다. (1) 글꼴을 Google Fonts에서 불러오지 않고 직접 제공(`src/app/layout.jsx`, `globals.css`). (2) YouTube 플레이어는 노래 카드에서 "YouTube로 듣기"를 누를 때만 불러옴(`src/components/SongCard.jsx`, `SongCard.module.css`). 방침도 이에 맞춰 고쳤습니다(시행일 2026-11-11). 전체 앱에는 아직 없으니, 합칠 때 이 파일들과 `src/app/privacy/page.jsx`를 **함께** 가져가야 방침과 동작이 맞습니다. 백엔드 쪽에서 할 일은 없습니다.
- 2026-11-11 이 저장소의 코드를 **타입스크립트에서 자바스크립트로** 바꿨습니다(`.ts` → `.js`, `.tsx` → `.jsx`, 타입 표기만 삭제, 동작 같음). 전체 앱은 타입스크립트 그대로 두면 됩니다. 자세한 안내는 `docs/2026-11-11-javascript-conversion.md`. 알아 둘 것:
  - 합치면 전체 앱은 화면(자바스크립트)과 서버(타입스크립트)가 섞입니다. 전체 앱 `tsconfig.json`이 `allowJs: true`라 빌드는 됩니다. 순서는 `README.md`의 "원본에 합칠 때".
  - 전체 앱의 `src/lib/types.ts`는 서버 코드가 쓰므로 지우지 말아 주세요. 프론트는 더 이상 이 파일을 import하지 않습니다. 그래서 API 응답 모양을 바꿔도 프론트 쪽에서는 **타입 오류로 드러나지 않습니다**. 바꿀 때는 꼭 알려 주세요(이 저장소의 `src/lib/types.js` 설명도 같이 고칩니다).
- 이 프론트 저장소를 따로 배포하게 되면 Supabase Authentication의 Redirect URLs에 `<배포 주소>/api/auth/callback`을 추가해야 소셜 로그인이 됩니다(지금 등록된 것은 `http://localhost:3000`과 기존 배포 주소).
