# 하루연결

선택한 날짜의 조각글과 완성된 그림의 저장된 장면 요약·태그에서 일반 주제를 찾고, 그 주제와 관련 있는 뉴스 한 건과 AI 삽화를 개인 계정에 저장합니다. **일기 날짜를 포함한 이전 한 달(한국 시간)** 보도를 사용합니다. 예를 들어 11월 4일 일기는 10월 4일 00:00부터 11월 4일 23:59:59.999까지의 기사에서 찾습니다. 이전 달에 같은 일자가 없으면 말일로 맞추며(3월 31일 → 2월 28일, 윤년은 29일), 오늘 일기는 실제 검색 시각까지로 제한합니다. 개인 그림 파일 자체를 AI로 분석하지 않습니다.

## 사용 방법

오늘 또는 날짜별 기록 화면의 하루연결 버튼을 누릅니다. 입력 중인 조각글은 먼저 저장합니다. 갤러리의 하루연결 카드나 하루만평의 메뉴로도 들어갈 수 있습니다.

하루연결 화면에서 일기 날짜를 고른 다음 **이날의 뉴스 연결하기**를 누릅니다. 그림이 없는 날도 저장된 조각글이 있으면 사용할 수 있습니다. 첫 방문이나 새로고침은 새 생성을 요청하지 않습니다. 이미 요청한 작업은 화면을 닫아도 서버에서 이어집니다.

결과에는 개인 그림(없으면 조각글), 뉴스 그림, 연결한 주제, 연결 이유, 사실 요약, 그림 해설, 기사 출처와 발행 시각, 검색 시각·기간을 구분해 보여 줍니다. 신뢰할 수 있는 관련 보도가 부족하면 `no_match`로 표시하고 다른 뉴스를 억지로 채우지 않습니다.

완성 결과는 재사용합니다. **뉴스 다시 연결하기**를 누르면 현재 저장된 기록과 일기 날짜 기준 한 달 범위로 새로 검색합니다. 기록이 바뀌면 기존 연결이 이전 기록을 바탕으로 했다는 안내가 나옵니다. 기존의 최근 7일 정책으로 저장된 결과에는 이전 검색 범위 안내를 표시하며, 자동으로 다시 생성하지 않습니다. 일기 날짜별 생성은 실패와 오래된 작업의 자동 복구를 포함해 총 3회까지이며, 뉴스 단계에서 그림 단계로 이어지는 것은 추가 횟수를 사용하지 않습니다. 일반 실패는 5분 후 수동으로 다시 요청할 수 있습니다.

## 데이터와 외부 호출

1. 로그인·본인 기록·AI 동의 여부를 확인한 후 DB 함수가 기록의 스냅샷을 만듭니다. 클라이언트가 조각글이나 사용자 ID를 임의로 지정해 생성할 수 없습니다.
2. 도구 없는 OpenAI Responses 요청에 조각글 내용과 저장된 장면 요약·태그를 보내 최대 두 개의 고정 주제 코드만 추출합니다. 작성 시각과 계정 식별자는 보내지 않습니다.
3. 서버가 주제 코드를 미리 정한 일반 검색어로 바꿉니다. 별개의 웹 검색 요청에는 이 일반 주제와 검색 기간만 전달합니다. 일기 원문·요약·태그·이미지·이전 응답 ID는 검색 단계에 전달하지 않습니다.
4. 허용된 언론사의 실제 검색 출처에 등장한 기사 URL, 발행 기간, 본문 확인 여부, 동일 사건에 대한 독립 매체 두 곳 이상의 근거를 검사합니다. 모델이 추출한 본문·발행 정보에 의존하므로 모든 사실을 독립적으로 보증하는 시스템은 아닙니다.
5. 공개 뉴스 근거와 일반 주제만으로 뉴스 요약·연결 이유·삽화 설명을 만듭니다. 개인 경험이나 감정, 기사의 영향 관계를 추측하도록 하지 않습니다.
6. 뉴스 내용을 저장하면 작업용 조각글 사본과 장면 요약·태그는 지웁니다. 다음 작업이 뉴스 삽화를 생성해 기존 비공개 `artworks` 저장소의 사용자 폴더에 저장합니다.

하루연결은 본인 전용이며 전시회와 하루만평의 공용 데이터에는 포함되지 않습니다. API 응답에 작업용 원문, 프롬프트, claim token, fingerprint는 넣지 않습니다. 일기나 제공자 응답 원문을 로그에 남기지 않습니다. 기존 OpenAI·Supabase 환경 설정을 재사용하며 새 API 키는 필요 없습니다. `DAILY_CONNECTION_ENABLED=false`로 새 작업을 중단할 수 있습니다.

## 작업과 삭제

뉴스 조사와 이미지 생성을 별도 작업 단계로 실행해 함수 실행 시간 안에 마칩니다. DB에서 작업별 10분 임대와 토큰을 발급하고, 토큰이 같은 worker만 상태를 저장합니다. 브라우저의 조회는 승인된 대기 작업만 재개하며, 별도의 Supabase dispatcher도 매분 대기·만료 작업을 확인합니다. 일반 실패나 이미 완성된 결과를 자동으로 다시 만들지는 않습니다.

동의를 철회하면 대기·진행 중인 연결을 취소하고 토큰을 무효화합니다. worker는 외부 호출과 저장 전후에 동의·계정·토큰을 다시 확인합니다. 이미 보낸 외부 요청 자체를 철회할 수는 없습니다. 아직 실행 중일 수 있는 작업의 임대가 끝나거나 worker가 취소를 확인할 때까지 마지막 글 삭제·탈퇴를 잠시 제한합니다.

마지막 조각글을 삭제하면 연결 결과도 제거하고, 생성 횟수만 별도 테이블에 보존해 삭제·재작성으로 한도를 초기화할 수 없게 합니다. 파일 정리가 일시 실패하면 계정 삭제 시 사용자 폴더 전체를 다시 정리합니다. 계정 삭제는 기존 그림과 하루연결 그림 파일을 정리한 뒤 계정·행을 삭제합니다.

## 운영 반영

새 마이그레이션 파일만 적용합니다. 기존 테이블을 재생성하는 과거 마이그레이션을 재실행하지 않습니다. 새 dispatcher는 기본 비활성 상태이며 `/api/connection-jobs` 배포 확인 후 `harujogak_private.connection_worker_control.enabled`를 켭니다. 기존 그림 worker와 하루만평 Cron은 별도로 동작합니다.

2026-11-25 운영 DB에는 `20261125121748_daily_connections.sql`을 적용했습니다. 별도 dispatcher는 매분 실행되며, 브라우저를 다른 날짜로 이동한 뒤에도 그림 단계를 자연 Cron 실행으로 시작하는 것을 확인했습니다.

## 검증

- 전체 자동 테스트 501개(Vitest 459개, Node 42개), ESLint, TypeScript 검사와 Next.js 프로덕션 빌드를 통과했습니다.
- 운영 DB의 한 트랜잭션에서 본인 요청, 같은 요청 ID 재사용, worker 권한, 뉴스→그림 단계 전환, 명시적 재검색, AI 동의 철회에 따른 취소·원문 제거 등 16개 검사를 통과한 뒤 전부 `ROLLBACK`했습니다. 외부 AI·HTTP·Storage 호출은 하지 않았습니다.
- 11월 16일 기록을 11월 25일 브라우저에서 연결해 검색 기간이 11월 19–25일로 잡히는 것을 확인했습니다. 관련 근거가 부족한 결과는 `no_match`로 저장되고 재방문 시 같은 결과와 사용 횟수를 표시했습니다.
- 개인 그림이 없는 11월 25일의 기존 조각글로 실제 뉴스 선정→출처 2개 표시→삽화 생성·비공개 저장→브라우저 표시를 확인했습니다. 별도 dispatcher의 자연 Cron 요청이 HTTP 200과 `ready`로 끝났고, 뉴스→그림 전환 및 새로고침 후에도 생성 횟수는 1회였습니다. 그림 확대와 나란히 보기, 저장 결과 재사용을 확인했습니다.
- 생성이 끝난 작업의 원문 사본·장면 요약·태그는 비워졌습니다. 운영 반영 전후 기존 조각글 31개와 그림 13개는 전체 행 해시가 같았습니다. 새 하루연결 결과 2건(`ready` 1건, `no_match` 1건)은 기능 결과로 남겨 두었습니다.

DB 자동 테스트는 단일 연결의 PGlite에서 실행합니다. 실제 여러 연결이 동시에 경합하는 부하 시험이나 모든 주제의 뉴스 매칭 정확도를 입증하지는 않습니다.

## 일기 날짜 기준 한 달로 변경 — 2026-11-25

- 이전의 검색 시점 최근 7일 정책을 일기 날짜 당일을 포함한 이전 한 달로 변경했습니다. 한 달은 달력 기준이며, 한국 시간의 시작·종료 경계와 윤년·월말을 검사합니다. 미래 기사나 일기 날짜 이후 보도를 대신 채우지 않습니다.
- 뉴스 요청에는 일기 원문 대신 기존의 허용된 일반 주제와 계산한 발행 기간·검색어만 전달합니다. 출처 URL·본문 확인·독립 매체 두 곳 조건은 유지합니다. 과거 기사를 탐색할 수 있도록 웹 도구 호출은 최대 6회이며, 검색 60초·전체 뉴스 처리 90초 제한은 유지합니다.
- 저장된 결과를 변경하지 않고 `rangeChanged`로 이전 범위를 안내합니다. 오늘의 결과는 최초 검색 시각을 기준으로 비교하므로 시간이 흘렀다는 이유만으로 정책 변경 안내가 뜨지 않습니다. 이전 범위의 미완료 그림 작업은 저장된 일반 주제로 다시 검색한 후 그림을 만들며, 이미 비운 일기 원문 사본을 다시 읽지 않습니다.
- 별도 스키마 변경이나 기존 결과 일괄 재생성은 없습니다. DB의 요청 직후 임시 기간은 API에서 새 예상 기간으로 표시하고, 뉴스 검색이 끝날 때 실제 사용 범위를 저장합니다.
- 전체 테스트 **567개(Vitest 525 + Node 42)**, lint, typecheck, production build 통과. 뉴스 72개·worker 35개·API 25개·화면 16개 검사에는 과거 기간 양쪽 경계, 월말·윤년, 기존 저장 결과 보존, 중간 작업 재개, 현재 날짜 캐시 재사용이 포함됩니다.
- 운영 배포 `dpl_DKnCmeb62N8E784CfZJdBRM6VV8M`가 READY이며 기존 운영 주소 세 곳에 반영됐습니다. 로그인된 실제 브라우저에서 11월 4일 일기의 새 범위가 `2026. 10. 4. – 2026. 11. 4.`로 표시되고, 기존 결과의 `11. 19. – 11. 25.` 범위·이전 범위 안내·다시 연결 버튼이 구분되는 것을 확인했습니다. 새 정책으로 실제 AI 검색·이미지 생성을 다시 요청하지는 않았습니다.
- 운영 DB의 기존 연결 5건은 검증 전후 상태·시도 횟수·검색 범위·선정 시각이 같았습니다. 검증 시점 최종 배포의 오류·치명적 오류 로그는 조회되지 않았습니다.
