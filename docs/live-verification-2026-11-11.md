## 범위와 남은 확인

- 이번 실제 검증은 기존 worker와 호환되는 수채화 한 건이다. 새 메타데이터까지 저장된 것을 확인했으며 예시 이미지나 모의 응답을 성공 결과로 사용하지 않았다.
- 이 로컬 검증 이후 새 UI와 worker의 Vercel 운영 배포를 완료했다. 운영 로그인 화면·인증된 빈 worker 호출은 확인했지만, 운영 브라우저의 로그인 후 생성·갤러리나 `crayon`·`story` 실생성을 검증한 것은 아니다.
- 새 이메일 가입·인증 메일·비밀번호 복구·카카오/Google OAuth는 이번 흐름에서 다시 검증하지 않았다. 기존 SMTP 수신자 제약은 그대로다.
- 자동 예약 마감·장애 복구·다시 그리기·공개 전시·큐레이터는 이번 실제 생성 시험 범위에 포함하지 않았다. 단위/DB 회귀 시험과 실제 서비스 시험을 구분한다.
- 보안 Advisor에는 의도된 인증 사용자용 SECURITY DEFINER RPC 경고와 내부 관리 테이블의 RLS 정책 없음 안내가 있다. 함수 내 소유권 확인과 실행 권한을 함께 점검했다. 유출 비밀번호 보호 비활성 경고도 기존 상태로 남아 있다. [Advisor 기준](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable), [비밀번호 보호 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

적용 파일명을 정리한 후 기존·추가 DB 회귀 테스트 **24개 통과**. 이번 실제 흐름에서는 애플리케이션 코드 수정이 필요하지 않았다.

배포 확인 단계에서 유료 GPT 생성 요청을 추가하지 않았다. 위 수채화 1건은 로컬에서 실제 외부 서비스 연결을 검증한 증거이며, 배포 후 Cron의 `idle`·빈 작업 응답과 함께 기록하더라도 실제 예약 생성·장애 복구까지 성공했다는 뜻은 아니다.
