# 실패 후 복구 점검 (2026-11-26)

하루만평에서 기사 근거 부족 결과를 다시 선정할 수 없던 문제를 수정한 뒤, 같은 종류의 상태 정지·응답 유실·로그인 변경 경로를 추가 점검했습니다.

## 재현하고 수정한 문제

| 경로 | 재현 조건과 이전 동작 | 수정한 동작 |
| --- | --- | --- |
| 하루만평 재선정 | 생성 POST 응답만 유실되고 첫 상태 조회가 이전 실패 행을 반환하면, 서버 작업이 끝나도 화면은 실패 상태에 남음 | 응답이 불확실한 요청은 짧은 관찰 기간에 상태를 다시 조회하며 중복 시작을 억제 |
| 하루만평·하루연결 대기시간 | 재시도 가능 시각의 상태 조회가 통신·서버 오류로 실패하면 다음 조회가 예약되지 않아 버튼이 잠김 | 보류 중인 상태 확인을 5초 뒤 다시 조회하고 성공 응답에 따라 버튼과 진행 상태를 갱신 |
| 생성 중 로그인 만료 | 처리 중이라는 이전 상태 때문에 401·403 응답 뒤에도 자동 조회가 반복됨 | 명확하게 거절된 조회는 자동 반복을 중단하고 수동 새로고침은 유지 |
| 프로필 계정 전환 | 처음 불러온 프로필을 계속 사용하여 계정 변경 뒤에도 외형·동의·미저장 값이 남음 | 계정 또는 로그인 세션이 바뀌면 새 계정 값으로 초기화하고 같은 세션의 미저장 편집은 보존 |
| 이전 프로필 저장 응답 | 계정 전환 이전 요청이 늦게 끝나 새 화면을 이동시키거나 저장 오류를 표시함 | 이전 세션의 저장 응답을 무시하고 오래된 저장 핸들러는 HTTP 요청 전에 차단 |

깨진 JSON 응답, 요청 시간 초과, 상태 조회 실패 후 화면 이탈·탭 숨김, 수동 재시도도 함께 검증합니다. 오류 복구용 반복 요청은 상태 조회(GET)이며, 하루연결 생성이나 `unavailable` 만평 재선정을 새로 승인하는 POST를 자동 반복하지 않습니다. 생성 횟수·대기시간·동의·출처·날짜 검증 정책은 유지합니다.

## 범위

- 전체 자동 테스트 **731개**(Vitest 689개·Node 42개), ESLint, TypeScript 검사, Next.js 프로덕션 빌드를 통과했습니다. 이번 점검의 회귀 테스트 28개가 포함되어 있습니다.
- 클라이언트 상태 처리와 프로필 세션 경계만 변경했습니다. 이번 추가 점검에는 새 DB 마이그레이션이 필요하지 않습니다.
- 지난 날짜의 조각 저장은 기존 응답 유실 조정, 조각 ID 재사용, 실패 후 내용 보존, 계정 변경 보호를 점검했으며 추가로 재현된 결함은 없었습니다.
- 모의 네트워크와 로그인 세션으로 회귀 테스트가 수정 전 실패하고 수정 후 통과하는 것을 확인했습니다. 운영 계정 전환이나 실제 통신 단절을 강제로 수행한 결과는 아닙니다.
- 운영 브라우저에서 기존 11월 21일 만평·기사 출처·그림이 정상 표시되는 것을 확인했습니다. 이 점검을 위해 새 유료 이미지나 사용자 기록을 생성하지 않았습니다.

이 문서는 이번 장애 복구 점검 기록입니다. 기능별 운영·DB 설정은 [하루만평](daily-cartoon.md), [하루연결](daily-connection.md), [프로필](art-profile.md), [하루세상 UI](haru-world-ui.md)를 참고합니다.
