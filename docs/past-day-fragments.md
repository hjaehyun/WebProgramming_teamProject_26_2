# 그림 없는 지난 날짜의 조각글

갤러리에서 오늘 이전 날짜를 누르면 그림이 없어도 그날의 조각글을 작성할 수 있습니다. 그림이 없어도 글은 계정에 저장되며 새로고침 후 같은 날짜에 남습니다. 월 선택으로 이전 달을 열거나 이번 달로 돌아올 수 있습니다.

## 사용법

1. 갤러리에서 월과 날짜를 고릅니다. 미래 날짜는 작성할 수 없습니다.
2. 조각글을 추가합니다. 저장한 조각을 누르면 **수정**, **지우기** 버튼이 나타납니다.
3. 글이 모이면 **이날의 그림 그리기**를 누릅니다. 입력 중인 글이 있으면 버튼명이 **조각 저장하고 그림 그리기**로 바뀝니다. 입력 중인 글과 진행 중인 저장을 마친 후 그 날짜의 기록으로 그림을 요청합니다.
4. 그림을 만드는 동안 해당 날짜의 글 편집은 잠시 잠깁니다. 완료된 그림은 기존과 같이 액자·음악·전시 기능을 이용합니다.

그림 없는 날짜는 `drafts[날짜]`, 그림 있는 날짜는 `artworks[날짜].entries`로 표시합니다. 이는 화면 데이터 구조일 뿐 두 경우 모두 Supabase `entries` 테이블에 저장합니다. 첫 그림이 만들어지면 글이 그림에 연결된 형태로 표시되며 다른 날짜의 기록은 그대로 유지됩니다.

## 날짜와 자동 생성

- 기록 대상 날짜(`entry_date`)와 실제 입력 시각(`created_at`)을 구분합니다. 과거 기록을 오늘 입력해도 과거 날짜에 보이며, 입력한 날짜가 기록 대상 날짜와 다르면 한국 시간 기준 **11/25 더함**처럼 실제 입력 월·일을 표시합니다.
- 과거 기록에는 지금의 위치나 날씨를 붙이지 않습니다.
- 그림이 없고 해당 날짜 당시에 작성한 조각이 남아 있는 날은 기존처럼 한국 시간 자정 이후 자동 생성 대상입니다. AI 처리에 동의했고 삭제 진행 중이 아닌 계정에 적용됩니다.
- 날짜가 지난 뒤 처음 보충한 조각만 있는 날은 자동 생성하지 않습니다. 작성자가 직접 **이날의 그림 그리기**를 눌러 시작합니다. 같은 날 글을 여러 번 보충하다가 매분 Cron에 의해 갑자기 편집이 잠기는 상황을 피하기 위한 규칙입니다.
- 하루 30개 조각과 그림 생성 시도 총 3회 제한(실패 포함)을 유지합니다. 그림이 있는 날의 마지막 글을 지우면 그림과 전시 연결도 제거되며, 삭제했다 다시 써도 생성 횟수는 초기화되지 않습니다.

## 구현

갤러리 달력과 날짜 상세 화면을 확장하고, Supabase의 `save_team_entry`, `edit_entry`, `remove_team_entry`가 과거의 그림 없는 날짜를 처리하도록 변경했습니다. `enqueue_closed_days`는 실제 작성 시각을 확인해 자동 생성 대상만 처리합니다. 인증, 본인 소유권, 계정 삭제 상태와 날짜별 잠금은 유지합니다.

새 마이그레이션 `20261125111300_past_day_drafts.sql`만 적용합니다. 기존 테이블을 재생성하거나 과거 마이그레이션 전체를 다시 실행하지 않습니다. 저장된 조각글·그림·하루만평은 이 마이그레이션으로 수정하지 않습니다.

## 검증 기록 — 2026-11-25

- 전체 자동 테스트 338개(Vitest 296개, Node 42개), ESLint, TypeScript, 프로덕션 빌드 통과.
- Supabase 운영 마이그레이션 적용 완료. 실제 인증 역할로 과거 글 추가·수정·삭제·재작성, 첫 그림의 대기 상태와 기록 스냅샷, 같은 요청의 중복 방지, 생성 대기 중 글 편집 차단을 트랜잭션 안에서 확인한 뒤 모두 롤백했습니다. 외부 AI 작업은 실행하지 않았습니다.
- Vercel 배포 `dpl_GRaDHBc2pyi3WbzeV7ow6MQg9XA3`가 READY이고 기존 운영 도메인에 반영됐습니다.
- 운영 브라우저에서 11월 24일의 빈 날짜를 열어 임시 글을 저장·수정하고 각 단계에서 새로고침 후 유지되는 것을 확인했습니다. 달력의 조각 수 표시, 이전 달 빈 날짜 열기, 돌아왔을 때 선택한 월 유지, 이번 달 복귀, 미래 날짜 직접 접근 차단도 확인했습니다.
- 임시 글 한 개를 정리한 후 기존 글 31개와 그림 13개의 전체 행 해시가 검증 전과 일치했습니다. 브라우저 콘솔 오류와 해당 배포의 error/fatal 런타임 로그는 조회 시점에 없었습니다.
- 이번 검증에서 과거 날짜의 실제 AI 이미지 완성까지 새로 실행하지는 않았습니다. 첫 생성 요청과 스냅샷 저장까지 운영 DB에서 검증했고, 기존 이미지 생성 파이프라인을 재사용합니다. 실제 한국 자정 통과 및 여러 DB 연결의 동시 잠금 경합은 재현하지 않았습니다.
