앱 비밀번호는 읽거나 복사하지 않았고 저장소·채팅·`.env`에 남기지 않았다. 기존 Resend 계정·키도 삭제하지 않았다. SMTP 설정 저장 확인만으로 실제 발송 성공을 판단하지 않는다.

Site URL은 `https://harujogak-hihellow18.vercel.app`이다. 기존 redirect 목록의 `http://127.0.0.1:3000/auth/callback`과 운영 `/auth/callback`을 유지했다. 가입·복구 메일 미리보기에서 Site URL 기반 `/auth/confirm`, `token_hash`, 각각 `type=email`·`type=recovery` 경로를 확인했으며 템플릿은 변경하지 않았다.

## 실제 수신·인증 확인

사용자는 발신 계정과 다른 본인 소유 주소에서 인증 메일을 받았다고 확인했다. 21:03:46(KST)의 Auth 확인에서 사용자 2명 모두 인증됐고 새 계정의 생성·인증 메일 요청 시각은 21:02:18, 인증 완료는 21:02:35.595, 마지막 로그인은 21:02:35.601이었다. 프로필·입력 완료 상태도 확인했다. 이메일 원문·사용자 ID·인증 링크·토큰은 기록하지 않는다.

사용자가 이미 인증과 프로필 입력까지 진행한 뒤 확인했으므로 미인증 중간 상태를 관측한 것은 아니다. 수신은 사용자 보고, 인증 완료는 Auth 메타데이터에 근거하며 받은편지함·SMTP 로그를 읽었다고 주장하지 않는다.

이후 사용자가 새 이메일 계정으로 비밀번호 로그인을 완료했다고 보고했다. 운영 `/today`의 로그인 상태·기록 0개·활성 입력과 `/me`의 새 계정·프로필 입력 완료·그림 0개·동화책 설정을 직접 확인했다. 새 계정 화면의 스크린샷은 로컬에 보관했으며 저장소에는 포함하지 않는다. 새 계정으로 일기 저장·GPT 생성은 수행하지 않았다.

21:10:08(KST)의 최종 읽기 확인에서는 계정 2명·이메일 인증 2명, 새 계정 기록 0개·그림 0개를 확인했다. 기존 계정의 기록 5개와 그림 3개도 유지됐고 그림은 모두 `ready`였다. 개인정보 원문이나 비밀번호는 기록하지 않았다.

## 남은 검증·운영 조건

- Gmail에는 발송 제한이 있다. 개인 계정은 하루 500통 초과 등으로 제한될 수 있으며, 프로젝트의 시간당 30통 제한과 별개다. [Google 안내](https://support.google.com/mail/answer/22839)
- Google 계정 비밀번호를 바꾸면 기존 앱 비밀번호가 폐기된다. 이 경우 새 앱 비밀번호를 Supabase에 직접 다시 설정해야 한다. [Google 안내](https://support.google.com/accounts/answer/185833)
- 새 SMTP에서 비밀번호 복구, OAuth 활성화, 운영 신규 기록 저장 및 자동 작업·중단 복구는 이번 가입 검증의 범위가 아니다. 동화책은 프로필 설정만 확인했고 실제 그림을 생성하지 않았다.
