# 하루만평

2026-11-25에 추가한 자동 뉴스 만평 기능입니다. `/cartoon`에서 날짜별 공용 만평과 같은 날짜의 내 그림을 비교합니다. 내 그림이 없으면 기록하기 안내를 보여줍니다.

## 동작

1. 오늘의 만평은 주요 저녁 뉴스가 나온 뒤 준비하도록 Vercel Cron이 한국 시간 매일 22시대에 `/api/cartoon-jobs`를 호출합니다(`0 13 * * *`, UTC). 플랫폼 일정의 정밀도에 따라 실제 시작 시각은 달라질 수 있습니다. 오늘 지면의 22시 이후 첫 방문도 작업을 자동 요청합니다. 지난날은 날짜 입력으로 선택한 뒤 생성 버튼을 누릅니다. 날짜를 둘러보거나 처음 조회하는 것만으로 과거 지면을 만들지는 않습니다.
2. Supabase의 날짜별 행과 원자적 선점으로 한 작업만 처리합니다. MBC 뉴스데스크와 SBS 8뉴스의 공식 날짜별 다시보기 목록에서 실제 보도 순서를 확인하고, 앞선 보도들을 뉴스 조사 후보로 전달합니다. 그중 해당 방송의 첫 보도로 확인된 사건과 같은 사건에 대한 독립 매체의 보도를 조사합니다.
3. 방송의 편집 우선순위는 서버의 공식 목록 파서가 확인한 정보만 사용합니다. 검색 모델이 임의로 주장한 '첫 뉴스'·'1면 기사'는 근거가 되지 않습니다. 기사 자체는 검색 응답의 출처 목록에 실제 등장한 허용 매체 기사 주소만 수용하고, 날짜·원문 확인 정보·동일 이슈 여부를 검사합니다. 이 두 종류의 근거로 대표 뉴스, 짧은 요약, 선정 이유와 만평 비유를 정합니다. 지난날 지면은 해당 한국 날짜의 23:59:59.999까지, 오늘 지면은 선정 시각까지 발행된 기사만 받습니다. 이후 사건 전개나 현재 뉴스를 과거 지면에 넣지 않도록 검색·선정에 같은 마감 시각을 전달합니다.
4. 선정 결과를 먼저 저장하고 이미지를 생성합니다. 그림은 비공개 `news-cartoons` 버킷에 저장합니다. 인증된 API만 1시간 유효한 이미지 주소를 제공합니다.
5. 화면에는 뉴스 요약, AI 만평 해설, 선정 시각과 클릭 가능한 원문 출처가 따로 표시됩니다. 새 선정 결과에는 실제 방송 배치를 확인한 근거 링크도 표시합니다. 내 일기·그림·계정 정보는 뉴스 검색이나 만평 생성으로 보내지 않습니다.

## 대표 뉴스 선정 기준

2026-11-26 점검에서 완성된 만평 8개 중 5개가 증시 관련이었습니다. 일부 날짜는 실제 저녁 뉴스의 선두와 일치했지만, 다른 날짜는 더 앞서 보도된 정치·사회 이슈를 제치고 증시가 선정됐습니다. 기존의 '1면감 사건을 고르라'는 AI 지시와 독립 매체 2곳 확인만으로는 편집 우선순위를 보증할 수 없었습니다. [점검 근거와 한계](daily-cartoon-selection-audit-2026-11-26.md)를 별도로 기록합니다.

새 선정은 **실제 저녁 종합뉴스 첫 보도로 확인된 사건**을 기준으로 합니다.

- MBC 뉴스데스크·SBS 8뉴스의 공식 날짜별 보도 목록에서 상위 3개 기사를 조사 출발점으로 수집합니다. 상위 3개라는 이유만으로 모두 최종 후보가 되는 것은 아니며, 최종 선정할 사건은 적어도 한 방송의 첫 보도와 연결돼야 합니다.
- 확인된 첫 보도들을 모두 비교 대상으로 삼고, 같은 사건에 대해 독립 매체 두 곳 이상의 당일 기사와 원문 사실을 확인해야 합니다. 같은 원보도의 전재는 독립 확인으로 세지 않습니다.
- 복수 방송이 공통으로 첫 보도에 배치한 사건을 먼저 고려합니다. 방송별 선두가 다르면 확인된 후보 사이에서 사회에 미치는 영향, 긴급성, 그날의 새로운 변화를 AI가 비교합니다.
- 경제 뉴스라는 이유로 감점하지 않고, 분야별 할당량이나 순환을 강제하지 않습니다. 여러 매체에 쉽게 노출되는 증시 수치라는 이유만으로 첫 보도 근거가 없는 사건을 대신 고르지도 않습니다.
- 과거 날짜는 그날 마감 시각까지 확인된 최신 전개를 우선합니다. 오전의 장중 낙폭·잠정 집계 등을 최종 결과인 것처럼 표현하지 않으며, 후속 보도로 달라진 점을 반영합니다.
- 화면의 선정 이유에는 확인된 방송 배치와 사건의 구체적인 변화·영향을 설명합니다. 사실 확인용 기사 출처와 편집 배치 확인용 공식 목록을 구분합니다.
- 원문 사실·발행일·독립 보도 또는 첫 보도 배치 근거를 확보하지 못하면 `unavailable`로 남깁니다. 다른 날짜나 검색하기 쉬운 사건으로 대체하지 않습니다.

실제 신문 지면의 1면 수록 여부나 전체 언론사의 보도량·조회수·검색량은 집계하지 않습니다. MBC·SBS가 확인 가능한 편집 근거이며, 모든 언론을 대표하는 객관적 '당일 1위'를 보장하지 않습니다. 공식 목록의 순서·날짜는 서버에서 검사하지만 기사 원문의 사실·발행 시각·동일 사건 판단은 웹 검색 모델의 추출과 판단에 여전히 영향을 받습니다. 방송 사이트의 구조 변경·접근 실패나 과거 자료 부족으로 선정이 불가능할 수 있습니다.

변경된 기준은 새로 뉴스를 선정하는 작업부터 적용합니다. 이미 선정해 저장한 뉴스와 완성된 만평은 유지하고, 이미지 단계만 재시도할 때는 저장된 선정 결과를 재사용합니다. 하루연결의 일기 주제·이전 한 달 기준에는 변화가 없습니다.

## 실패와 비용 제한

- 하루 한 행과 완성 그림 한 장을 재사용하며, 준비된 날짜를 다시 생성하지 않습니다.
- 실패 후 15분, 중단된 작업의 선점 후 10분이 지나면 방문 화면에서 다시 요청할 수 있습니다. 날짜별 최대 3회입니다. 과거의 실패 결과는 재시도 버튼으로 다시 요청하고, 이미 대기 중이거나 중단된 작업은 해당 지면에서 재개합니다. 방문자가 없는 날의 실패를 자동 재시도하는 추가 Cron은 없습니다.
- 기사 근거가 부족하면 `unavailable`로 기록하고 해당 시도에서는 그림을 만들지 않습니다. 남은 횟수가 있으면 15분 뒤 **뉴스 다시 선정하기**로 같은 날짜의 기사를 다시 검색할 수 있습니다. 재시도 시각이 없는 기존 `unavailable` 결과는 즉시 수동 재선정할 수 있습니다. 날짜별 최대 3회는 뉴스 검색 실패를 포함하며 재선정해도 사용 횟수를 초기화하지 않습니다.
- `unavailable`의 재선정은 사용자가 버튼을 눌러 요청할 때만 시작합니다. 페이지 조회·새로고침·대기 시간 만료·탭 재활성화·정기 Cron은 자동으로 재선정하지 않습니다. 수동 요청은 `claim_daily_cartoon(date, boolean)`에 명시적으로 재선정 의사를 전달하며, 기존 한 인자 함수는 재선정 없이 처리하는 호환 래퍼입니다. 두 함수 모두 service_role만 실행할 수 있습니다.
- 오래된 날짜일수록 검색 가능한 기사 근거가 부족할 수 있으며, 다시 검색해도 뉴스가 선정되지 않을 수 있습니다. 다른 날짜의 기사로 대신 채우지 않습니다. 미래 날짜는 조회·생성할 수 없습니다.
- 뉴스 선정 체크포인트가 있으면 이미지 재시도에서 다시 검색하지 않습니다. 동시 요청을 막지만, 외부 제공자 응답 유실 등에 따른 과금의 정확히 한 번 실행까지 보장하지는 않습니다.
- 공식 방송 목록 조회·뉴스 검색·선정은 합계 최대 100초, 이미지 API는 최대 180초, Vercel 함수는 최대 300초입니다.
- 과거 기사 검색에는 한글·ISO 날짜와 공식 목록에서 확인한 사건을 함께 전달합니다. 전체 시간 제한과 출처·발행일 기준을 유지하며, 근거 부족 시 기사 원문 대신 후보 수·검증 통과 수 등의 진단 정보만 로그에 남깁니다.

기존 `OPENAI_API_KEY`, `OPENAI_TEXT_MODEL`, `OPENAI_IMAGE_MODEL`, `SUPABASE_SECRET_KEY`, `CRON_SECRET`을 사용합니다. 텍스트 모델은 Responses 웹 검색과 Structured Outputs를 지원해야 합니다. 별도 뉴스 API 키는 필요하지 않습니다. `DAILY_CARTOON_ENABLED=false`는 새 생성을 중지하며 기존 만평 조회는 유지합니다.

DB에는 이 기능의 새 마이그레이션만 먼저 적용한 뒤 앱을 배포합니다. 기존 음악 테이블을 지우는 초기 마이그레이션을 다시 실행하지 않습니다. 새 테이블은 개인 일기와 외래 키를 맺지 않으며 기존 일기·그림을 수정하지 않습니다. 브라우저 역할은 결과 일부만 읽고 생성·선점·Storage 직접 접근을 할 수 없습니다.

## API

- `GET /api/cartoons?date=YYYY-MM-DD`: 로그인 후 지면, 최근 31개 발행 날짜, 오늘 날짜, 시작 가능 여부와 시작 예정 시각을 조회합니다. 미래 날짜는 거절합니다.
- `POST /api/cartoons`, 본문 `{ "date": "YYYY-MM-DD" }`: 로그인과 동일 출처를 확인하고 선택한 날짜의 작업을 요청합니다. `{}`는 기존 클라이언트와 호환되도록 오늘을 선택합니다. 오늘은 22시 이후, 지난날은 시간 제한 없이 요청할 수 있습니다. 응답 이후 `after()`에서 처리하며 진행 상태는 조회 API로 확인합니다. 완성 지면과 해당 날짜의 시도 횟수는 초기화하지 않습니다.
- `GET|POST /api/cartoon-jobs`: `Authorization: Bearer CRON_SECRET`이 필요합니다. 환경의 기존 Cron 비밀값은 로그나 응답에 포함하지 않습니다.

검증은 뉴스 출처·날짜 검증, DB 권한·동시 요청·시도 제한, API 인증, 생성 작업의 실패 복구를 포함합니다. 모의 API와 PGlite 검증은 실제 뉴스 검색 및 이미지 생성 검증과 구분합니다.
