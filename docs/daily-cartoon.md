# 하루만평

2026-11-25에 추가한 자동 뉴스 만평 기능입니다. `/cartoon`에서 날짜별 공용 만평과 같은 날짜의 내 그림을 비교합니다. 내 그림이 없으면 기록하기 안내를 보여줍니다.

## 동작

1. 오늘의 만평은 Vercel Cron이 한국 시간 매일 19시대에 `/api/cartoon-jobs`를 호출해 준비합니다(`0 10 * * *`, UTC). 플랫폼 일정의 정밀도에 따라 실제 시작 시각은 달라질 수 있습니다. 오늘 지면의 19시 이후 첫 방문도 작업을 자동 요청합니다. 지난날은 날짜 입력으로 선택한 뒤 생성 버튼을 누릅니다. 날짜를 둘러보거나 처음 조회하는 것만으로 과거 지면을 만들지는 않습니다.
2. Supabase의 날짜별 행과 원자적 선점으로 한 작업만 처리합니다. OpenAI 웹 검색에서 해당 한국 날짜에 발행된 기사를 찾고, 같은 사건에 대한 서로 다른 매체의 보도 두 개 이상을 확인합니다.
3. 검색 응답의 출처 목록에 실제 등장한 허용 매체 기사 주소만 수용합니다. 날짜·원문 확인 정보·동일 이슈 여부를 검사한 근거 목록으로 대표 뉴스, 짧은 요약, 선정 이유와 만평 비유를 정합니다. 지난날 지면은 해당 한국 날짜의 23:59:59.999까지, 오늘 지면은 선정 시각까지 발행된 기사만 받습니다. 이후 사건 전개나 현재 뉴스를 과거 지면에 넣지 않도록 검색·선정에 같은 마감 시각을 전달합니다. 객관적인 뉴스 순위 집계는 아닙니다. 기사 발행 시각과 원문 사실은 검색 모델이 추출한 근거이며 별도의 원문 수집기는 없습니다.
4. 선정 결과를 먼저 저장하고 이미지를 생성합니다. 그림은 비공개 `news-cartoons` 버킷에 저장합니다. 인증된 API만 1시간 유효한 이미지 주소를 제공합니다.
5. 화면에는 뉴스 요약, AI 만평 해설, 선정 시각과 클릭 가능한 원문 출처가 따로 표시됩니다. 내 일기·그림·계정 정보는 뉴스 검색이나 만평 생성으로 보내지 않습니다.

## 대표 뉴스 선정 기준

2026-11-26부터 뉴스 조사와 최종 선정에 **그날 종합신문 1면의 대표 기사로 실릴 만한 사건**이라는 편집 기준을 함께 적용합니다.

- 그날 새로 벌어진 변화의 중요성, 사회에 미치는 영향의 범위와 심각성, 긴급성 또는 지속적인 중요성을 우선합니다.
- 근거가 충분하면 정치·사회·경제·국제·과학·문화 등 여러 분야의 사건 2~3개를 비교합니다. 후보 수나 분야 순환을 강제하지 않으며, 충분한 근거를 갖춘 중대한 사건 하나만 확인돼도 선택할 수 있습니다.
- 같은 사건의 독립 매체 두 곳 이상 확인은 기본 조건입니다. 기사 수가 많거나 찾기 쉽다는 이유만으로 대표 사건을 정하지 않습니다.
- 통상적인 증시 마감·반복 통계·홍보성 발표·연예인 근황은 그 자체로 우선하지 않습니다. 다만 기록적인 시장 충격처럼 넓은 영향을 근거로 확인할 수 있는 사건은 후보가 됩니다.
- 화면의 선정 이유에는 그날의 구체적인 변화와 그 영향 대상을 설명하도록 요구합니다. 두 매체가 보도했다는 사실만으로 설명을 끝내지 않습니다.

이는 AI에 적용한 편집 판단 지침입니다. 실제 신문의 1면이나 언론사 홈페이지 배치를 수집하지 않으며, 조회수·검색량·전체 보도량을 집계하거나 수치로 순위를 계산하지 않습니다. 따라서 실제 1면 수록, 메인 배치, 최다 조회, 객관적인 당일 1위라는 주장을 하지 않도록 지시합니다. 제한된 검색 후보와 모델의 판단에 영향을 받으며, 모의 테스트가 편집 판단의 품질까지 보증하지는 않습니다.

변경된 기준은 새로 뉴스를 선정하는 작업부터 적용합니다. 이미 선정해 저장한 뉴스와 완성된 만평은 유지하고, 이미지 단계만 재시도할 때는 저장된 선정 결과를 재사용합니다. 하루연결의 일기 주제·이전 한 달 기준에는 변화가 없습니다.

## 실패와 비용 제한

- 하루 한 행과 완성 그림 한 장을 재사용하며, 준비된 날짜를 다시 생성하지 않습니다.
- 실패 후 15분, 중단된 작업의 선점 후 10분이 지나면 방문 화면에서 다시 요청할 수 있습니다. 날짜별 최대 3회입니다. 과거의 실패 결과는 재시도 버튼으로 다시 요청하고, 이미 대기 중이거나 중단된 작업은 해당 지면에서 재개합니다. 방문자가 없는 날의 실패를 자동 재시도하는 추가 Cron은 없습니다.
- 기사 근거가 부족하면 `unavailable`로 기록하고 그날의 만평을 만들지 않습니다. 오래된 날짜일수록 검색 가능한 기사 근거가 부족할 수 있으며, 다른 날짜의 기사로 대신 채우지 않습니다. 미래 날짜는 조회·생성할 수 없습니다.
- 뉴스 선정 체크포인트가 있으면 이미지 재시도에서 다시 검색하지 않습니다. 동시 요청을 막지만, 외부 제공자 응답 유실 등에 따른 과금의 정확히 한 번 실행까지 보장하지는 않습니다.
- 검색·선정은 합계 최대 100초, 이미지 API는 최대 180초, Vercel 함수는 최대 300초입니다.
- 과거 기사 검색에는 한글·ISO 날짜가 포함된 검색어를 별도로 전달하며, 후보 발견과 서로 다른 원문 확인을 위해 웹 도구 호출 상한을 6회로 둡니다(오늘은 기존 3회). 전체 시간 제한과 출처·발행일 기준은 같습니다. 근거 부족 시 원문 대신 후보 수·검증 통과 수만 진단 로그에 남깁니다.

## 파일과 설정

| 위치 | 역할 |
| --- | --- |
| `src/app/cartoon/` | 신문 형태의 지면, 날짜 선택, 두 그림 비교, 진행 상태와 출처 |
| `src/server/cartoon-news.ts` | 웹 검색, 뉴스 근거 검증, 대표 뉴스·만평 기획 |
| `src/server/cartoons.ts` | 생성 선점, 체크포인트, 이미지 저장, 복구, 응답 구성 |
| `src/server/cartoon-handlers.ts` | 로그인·요청 출처 검사와 Cron 비밀값 검사 |
| `supabase/migrations/20261125103138_daily_editorial_cartoons.sql` | 새 테이블·RPC·비공개 버킷·접근 권한 |
| `supabase/migrations/20261125125132_past_daily_cartoons.sql` | 기존 데이터를 보존하면서 지난 날짜의 생성·재시도 허용 |
| `vercel.json` | 매일 자동 발행 일정 |

기존 `OPENAI_API_KEY`, `OPENAI_TEXT_MODEL`, `OPENAI_IMAGE_MODEL`, `SUPABASE_SECRET_KEY`, `CRON_SECRET`을 사용합니다. 텍스트 모델은 Responses 웹 검색과 Structured Outputs를 지원해야 합니다. 별도 뉴스 API 키는 필요하지 않습니다. `DAILY_CARTOON_ENABLED=false`는 새 생성을 중지하며 기존 만평 조회는 유지합니다.

DB에는 이 기능의 새 마이그레이션만 먼저 적용한 뒤 앱을 배포합니다. 기존 음악 테이블을 지우는 초기 마이그레이션을 다시 실행하지 않습니다. 새 테이블은 개인 일기와 외래 키를 맺지 않으며 기존 일기·그림을 수정하지 않습니다. 브라우저 역할은 결과 일부만 읽고 생성·선점·Storage 직접 접근을 할 수 없습니다.

## API

- `GET /api/cartoons?date=YYYY-MM-DD`: 로그인 후 지면, 최근 31개 발행 날짜, 오늘 날짜, 시작 가능 여부와 시작 예정 시각을 조회합니다. 미래 날짜는 거절합니다.
- `POST /api/cartoons`, 본문 `{ "date": "YYYY-MM-DD" }`: 로그인과 동일 출처를 확인하고 선택한 날짜의 작업을 요청합니다. `{}`는 기존 클라이언트와 호환되도록 오늘을 선택합니다. 오늘은 19시 이후, 지난날은 시간 제한 없이 요청할 수 있습니다. 응답 이후 `after()`에서 처리하며 진행 상태는 조회 API로 확인합니다. 완성 지면과 해당 날짜의 시도 횟수는 초기화하지 않습니다.
- `GET|POST /api/cartoon-jobs`: `Authorization: Bearer CRON_SECRET`이 필요합니다. 환경의 기존 Cron 비밀값은 로그나 응답에 포함하지 않습니다.

검증은 뉴스 출처·날짜 검증, DB 권한·동시 요청·시도 제한, API 인증, 생성 작업의 실패 복구를 포함합니다. 모의 API와 PGlite 검증은 실제 뉴스 검색 및 이미지 생성 검증과 구분합니다.
